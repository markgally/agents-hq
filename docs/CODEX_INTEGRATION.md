# Codex Integration

AGENTS HQ runs every agent through the Codex App Server that ships inside the installed Codex. The backend
starts `codex app-server --listen stdio://` as a child process and exchanges newline-delimited JSON-RPC
messages with it. The browser never talks to Codex.

Everything in the "Verified on this machine" sections below was observed by running `tools/codex_probe.py`
against the real installation on 2026-11-24. Nothing here is taken from online documentation.

## Installed environment (verified)

| Item | Value |
|---|---|
| Executable | `codex.exe` inside the Codex desktop app package (`OpenAI.Codex`), found through `Get-AppxPackage` |
| Version | `codex-cli 0.171.0-alpha.13.2` |
| `codex` on PATH | No. AGENTS HQ therefore locates the desktop app's copy at start-up |
| Sign-in | `codex login status` -> "Logged in using ChatGPT". `account/read` -> account type `chatgpt`, plan type `team` |
| Windows sandbox | `windowsSandbox/readiness` -> `ready` |
| App server label | "[experimental]" in `codex --help` for this version |

The plan type reported by Codex on this machine is `team`, not Plus. AGENTS HQ shows whatever Codex reports.

## Schema

`docs/codex-schema/` holds the JSON schema generated by the installed binary:

```
codex app-server generate-json-schema --out docs/codex-schema
```

Regenerate it after a Codex update. `py -3 tools/schema_summary.py methods` lists the methods it contains
(110 client requests, 1 client notification, 10 server requests, 87 server notifications in this version).

## Verified behaviour

- A turn with the prompt "Reply with exactly: AGENTS HQ probe OK" completed in 3.9 s. Notification order:
  `thread/started`, `thread/status/changed` (active), `turn/started`, `item/started` + `item/completed`
  (`userMessage`), `item/started` (`agentMessage`), `item/agentMessage/delta` x5, `item/completed`
  (`agentMessage`), `thread/tokenUsage/updated`, `account/rateLimits/updated`, `thread/status/changed` (idle),
  `turn/completed` (`status: completed`).
- A thread created by one app-server process was resumed by a second process and answered a question about
  its previous reply correctly. Threads therefore survive an AGENTS HQ restart.
- Threads are durable as soon as `thread/start` returns (`ephemeral: false`, a rollout path exists). AGENTS HQ
  still creates a thread only when an agent is first used, so unused agents cost nothing.
- Resuming an unknown thread id fails with JSON-RPC error `-32600` "no rollout found for thread id ...".
  AGENTS HQ marks such an association unavailable; it never creates a replacement on its own.
- `thread/start` honoured `sandbox: "read-only"` and `approvalPolicy: "on-request"`
  (response: `{"type":"readOnly","networkAccess":false}`).
- Framing: 0 malformed lines, 0 invalid messages, no stderr output during the probes.

## Codex desktop interoperability (verified)

- AGENTS HQ and the desktop app share the same Codex home, so `thread/list` from AGENTS HQ returns threads
  created in the desktop app (originator `Codex Desktop`), and threads created by AGENTS HQ are stored in the
  same history with originator `agent_hq`.
- Associating an existing thread with an agent is supported through `thread/list` and `thread/resume`.
- Not verified: whether the desktop app refreshes an open thread when AGENTS HQ adds a turn to it. AGENTS HQ
  does not claim live synchronisation.
- There is no documented way in this version for AGENTS HQ to tell the desktop app to open a thread, so no
  "Open in Codex" button is offered.
- Two clients writing to one thread at the same time is unsafe. AGENTS HQ warns before associating a thread
  that did not originate in AGENTS HQ and asks the user not to use that thread in the desktop app while an
  agent is working.

## What AGENTS HQ never does

- Read, copy, or modify Codex credential files, session files, databases, cookies, or desktop storage.
- Drive the Codex desktop window, scrape ChatGPT, or call private endpoints.
- Start a sign-in with an API key, switch billing, or call `account/rateLimitResetCredit/consume` or
  `account/sendAddCreditsNudgeEmail`.
- Use the `danger-full-access` sandbox.

## Usage limits

All seven agents share one account and one allowance. At probe time Codex reported 69% of the 5-hour window
and 25% of the weekly window used. When Codex reports no figures, AGENTS HQ shows "Usage information
unavailable".
